Evidence before action

Sidq verifies schema, lineage, governance, ownership, and documented claims before an agent acts. Its deterministic enforcement path returns PASS, WARN, or BLOCK—and can write an evidence receipt back to DataHub for independent re-checking.

01 / The trust contract

Context is trusted only while its evidence holds.

Sidq does not turn missing proof into confidence. It checks the context, makes one reproducible decision, and gives later agents something they can independently re-evaluate.

  1. 01 Context

    Schema, lineage, governance, and documented claims arrive from DataHub.

  2. 02 Evidence check

    Sidq cross-checks those claims — and, when configured, the source itself.

  3. 03 PASS / WARN / BLOCK

    One deterministic policy decides. Missing evidence is named, never silently treated as clean.

  4. 04 Receipt

    An explicit audit can record the decision context in DataHub for later re-verification.

  5. 05 Next agent

    It re-checks the receipt for itself, then acts or stops on what still holds.

03 / Shared trust

The next agent verifies for itself.

A receipt is not authority. A separate reader re-reads the graph context and checks the receipt’s policy hash and age again, then answers on three axes it never collapses: does the receipt apply, what did it decide, and what may you do.

  • Current PASS → continue.
  • Current WARN → review or escalate.
  • Current BLOCK → stop. It was checked and refused — never shown as unverified.
  • Missing, stale, or unreadable → NOT VERIFIED → check again.

This hosted demo reads a persisted receipt from DataHub and judges whether it still holds; it never trusts the writer's response.

          03Security, reliability & operationsThe platform questions, answered without interrupting the story.
          

      

        

          
07 / Operations

          
The questions a platform team asks.

        

        

          

            
Data privacy

            
Catalog audits read metadata only. Receipt writes are explicit opt-ins into your catalog. The separate sidq claims verification runs bounded read-only SQL inside the source; query results never enter a model or leave your infrastructure. The optional reader sees documentation text only.

          

          

            
Reliability

            
Byte-identical verdicts. Same captured diff, graph snapshot, policy, configuration, code revision, and canonical serialization ⇒ same output. A CI-enforced suite guards the headline reproducibility claims — re-derive and compare, don't trust.

          

          

            
Model drift

            
No model can block or grant permission. The deterministic rule ships in the blocking path. The optional documentation reader may extend WARN coverage after rules abstain; it loads a pinned revision and reports its head fingerprint and threshold, so changes are attributable. Policy changes rotate the hash and invalidate old receipts explicitly.

          

          

            
Monitoring

            
Receipts are the dashboard. sidq.* properties are queryable in DataHub. sidq verify computes whether each recorded Receipt still holds against current context, policy, and age; audits report missing coverage explicitly.

          

          

            
Cost

            
Zero API fees, explicit compute. Open source and self-hosted. Gate, audit, repair, and swarm do not call a model; the optional reader runs locally. MCP time is budgeted per run. A valid Receipt can avoid repeat work; concurrent workers may still duplicate an examination because the protocol is at-least-once, not exactly-once.
