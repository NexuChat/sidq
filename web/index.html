Catalog truth verification · DataHub-native

DataHub says the column exists. The source says it does not.

Sidq blocks the agent before it builds on the disagreement — and, on request, writes the proof back through DataHub’s official MCP tools. The judged path is deterministic: PASS, WARN, or BLOCK. No LLM decides it.

01 Catalog vs reality

          
The headline, demonstrated.

          
Comparing a catalog with itself finds contradictions. It cannot find the case where the catalog is perfectly consistent and simply out of date. So Sidq also checks the live source.


          

            

              
DataHub says

              
raw.customers.email

              
Ingested, indexed, and what every agent planning against this table will read.

            

            

              
PostgreSQL says

              
raw.customers.email_address

              
Renamed by make demo-break. Nothing was re-ingested, which is exactly how this happens in production.

            

          


          
BLOCK — on the context, before the agent plans against a column that no longer exists.

          
Neither side of that comparison is available to a tool that only reads metadata. The nearest live proof on this page is the first button above: sidq claims takes what DataHub documents about a field, compiles it to bounded read-only SQL, runs it against the source, and lets the deterministic engine judge the row count that comes back. The schema-drift demo itself needs the local PostgreSQL from the runbook, because it alters a real table.

03 As a team

          
Four agents, one catalog, no boss.

          
The receipts are not only the output — they are the only shared state four concurrent auditors have. No coordinator, no message bus, no lock service, no shared filesystem. One is killed thirty seconds in, and nothing is stranded, because nothing was ever assigned to it.


          
Recorded, not runnable here — and that is the point. Every proof button on this page runs a command that cannot write to a catalog. The swarm coordinates by writing, so it can never be one of them; a read-only swarm would demonstrate nothing. This is the verbatim output of make swarm-demo against a DataHub OSS v1.5.0.6 quickstart, run swarm-1786323944. Run it yourself with the five-command runbook.

06 The receipt

          
The next agent verifies for itself.

          
A receipt is not authority. A separate reader re-reads the graph context, re-checks policy hash and age, and answers on three axes it never collapses: does it apply, what did it decide, what may you do.


          

            
Current PASSContinue.

            
Current WARNReview or escalate.

            
Current BLOCKStop. Checked and refused — never shown as unverified.

            
NOT VERIFIEDMissing, stale, or unreadable. Check again.
